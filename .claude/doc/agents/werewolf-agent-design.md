# 狼人智能体 (WerewolfAgent) 设计文档

## 概述

WerewolfAgent是基于Casevo框架开发的狼人杀游戏中狼人角色的AI智能体实现。该智能体通过思维链系统、提示词模板和记忆机制，实现复杂的角色扮演、逻辑推理和策略决策功能。

## 架构设计

### 核心架构

WerewolfAgent继承自Casevo的AgentBase基类，采用模块化设计架构：

- **基础智能体层**: 提供AgentBase的核心功能，包括记忆系统、上下文管理
- **思维链处理层**: 实现多步骤推理和决策逻辑
- **提示词模板层**: 通过Jinja2模板生成角色化的提示词
- **游戏状态层**: 管理狼人杀游戏的特定状态信息
- **策略决策层**: 实现狼人角色的核心游戏策略

### 组件关系

- **ModelBase**: 提供PromptFactory、MemoryFactory等工厂类
- **PromptFactory**: 管理Jinja2模板的加载和渲染
- **ThoughtChain**: 实现多步骤思维推理过程
- **Memory**: 存储短期和长期记忆信息
- **LLM Interface**: 与大语言模型的交互接口

## 智能体特性

### 角色特性

#### 基本属性
- **身份**: 狼人阵营成员，需要隐藏真实身份
- **目标**: 消灭好人阵营，优先清除威胁角色
- **协作**: 与狼队友进行信息协调和策略配合
- **伪装**: 扮演平民或神职角色，避免身份暴露

#### 性格特征
- **狡猾性**: 善于伪装和欺骗，制造误导信息
- **冷静性**: 在压力下保持逻辑清晰和决策稳定
- **团队意识**: 主动配合狼队友，实现整体战略目标
- **观察力**: 敏锐识别他人发言的细节和逻辑漏洞

### 认知能力

#### 逻辑推理
- **身份推断**: 基于有限信息推测其他玩家角色
- **威胁评估**: 量化其他玩家对狼人阵营的威胁程度
- **行为分析**: 识别发言模式、投票行为中的异常
- **矛盾检测**: 发现其他玩家发言中的逻辑不一致

#### 策略思维
- **短期规划**: 制定当前轮次的最优行动方案
- **长期布局**: 考虑多轮游戏进程的整体策略
- **风险控制**: 平衡激进策略与身份暴露风险
- **适应性调整**: 根据游戏局势变化调整策略

## 功能模块

### 夜晚行动模块 (night_action)

#### 功能描述
负责狼人夜晚阶段的击杀决策，是狼人的核心攻击能力。

#### 决策流程
1. **威胁评估**: 分析所有潜在目标的威胁等级
2. **概率分析**: 计算各目标为神职角色的概率
3. **团队协调**: 考虑狼队友的意见和协调需求
4. **风险评估**: 评估击杀选择的暴露风险
5. **最终决策**: 综合考虑后选择最优击杀目标

#### 决策因素
- **角色概率**: 目标为预言家、女巫、猎人等关键角色的概率
- **威胁等级**: 目标对狼人阵营的威胁程度
- **状态信息**: 目标的存活状态、技能使用情况
- **团队因素**: 与狼队友的协调需要和保护需求
- **风险评估**: 击杀后对自身和团队的影响

### 白天讨论模块 (day_discussion)

#### 功能描述
负责白天讨论阶段的发言生成，实现角色伪装和信息引导。

#### 发言策略
1. **身份强化**: 通过符合伪装身份的发言加强可信度
2. **逻辑分析**: 对游戏局势进行表面上的客观分析
3. **怀疑引导**: 暗示特定玩家的可疑性，转移注意力
4. **信息控制**: 控制信息流向，误导好人阵营判断
5. **自我保护**: 避免发言中暴露狼人身份信息

#### 发话要素
- **立场表达**: 作为"好人"阵营的立场和态度
- **分析内容**: 对当前游戏局势的表面分析
- **怀疑对象**: 提出值得怀疑的玩家名单和理由
- **行为建议**: 引导其他玩家的投票和行动方向
- **情感表达**: 展现符合角色的情绪反应

### 辩护模块 (defense)

#### 功能描述
当被质疑或指控时进行辩护，保护自己免于被投票出局。

#### 辩护策略
1. **事实辩驳**: 指出指控中的事实错误和逻辑漏洞
2. **身份证明**: 提供支持自己"好人"身份的"证据"
3. **转移焦点**: 将怀疑转移到其他更可疑的玩家
4. **情感共鸣**: 获得其他玩家的同情和支持
5. **逻辑反驳**: 用看似合理的逻辑反驳指控

#### 辩护要素
- **指控回应**: 对具体指控内容进行逐条回应
- **证据提供**: 提供支持自己清白的"证据"
- **动机分析**: 分析指控者可能的动机和目的
- **反质疑**: 对指控者进行反质疑
- **呼吁理性**: 请求其他玩家客观理性判断

### 投票模块 (vote)

#### 功能描述
在投票阶段做出投票决策，平衡团队利益和身份保护。

#### 投票策略
1. **保护队友**: 避免投票给狼队友，必要时提供掩护
2. **清除威胁**: 优先投票给对狼人威胁最大的角色
3. **身份隐藏**: 投票行为要符合伪装身份的逻辑
4. **影响控制**: 通过投票影响其他玩家的判断
5. **随机因素**: 在必要时制造一定的投票随机性

#### 决策因素
- **团队利益**: 投票对狼人团队整体利益的影响
- **身份保护**: 投票行为是否会暴露自己的狼人身份
- **威胁评估**: 候选人对狼人阵营的威胁程度
- **紧急程度**: 当前投票的紧急性和必要性
- **成功率评估**: 投票成功的概率和影响

### 反思模块 (reflect)

#### 功能描述
对自身在游戏中的表现进行反思和总结，制定改进策略。

#### 反思内容
1. **表现评价**: 客观评价自己的游戏表现和决策质量
2. **问题识别**: 识别决策中的问题和改进空间
3. **策略调整**: 制定下一阶段的策略调整方案
4. **技能提升**: 规划个人技能和能力的提升方向
5. **经验总结**: 提取成功经验和失败教训

#### 反思维度
- **决策质量**: 各轮决策的准确性和有效性
- **伪装效果**: 身份伪装的成功程度和暴露风险
- **团队配合**: 与狼队友的协作效果
- **策略执行**: 既定策略的执行情况和效果
- **适应性**: 对局势变化的适应和调整能力

## 思维链系统

### 设计理念

WerewolfAgent采用基于Casevo框架的思维链系统，将复杂的决策过程分解为多个可执行的步骤，每个步骤都有明确的输入、处理和输出。

### 思维链类型

#### JsonStep思维链
用于需要结构化输出的决策场景，如夜晚击杀、投票决策。

- **处理过程**: 接收输入数据，通过LLM生成JSON格式的决策结果
- **数据预处理**: 通过pre_process方法标准化输入数据
- **输出解析**: 解析JSON结果，提取决策信息
- **错误处理**: 处理解析失败和重试逻辑

#### 自定义思维链步骤
为每个功能模块专门设计的处理步骤，包含游戏逻辑和业务规则。

### 思维链配置

每个思维链都包含以下核心组件：
- **提示词模板**: 使用Jinja2模板生成LLM提示词
- **输入验证**: 验证输入数据的完整性和有效性
- **输出解析**: 解析和验证LLM的输出结果
- **错误恢复**: 处理异常情况并提供回退方案

## 提示词系统

### 模板架构

采用Jinja2模板引擎，支持动态参数注入和条件渲染。

#### 模板组织结构
- **模板文件**: 存储在app/prompts/werewolf/目录下
- **命名规范**: 按功能模块命名，如night_action.txt、defense.txt
- **变量标准**: 使用Casevo标准变量结构

#### 变量系统
- **agent.description**: 智能体的角色描述信息
- **agent.context**: 智能体的上下文信息
- **model.context**: 模型级别的上下文信息
- **extra.***: 额外的输入参数和数据

### 模板设计原则

#### 角色一致性
- 每个模板都强化特定的角色身份
- 保持语言风格和思维模式的一致性
- 避免暴露狼人身份的敏感信息

#### 逻辑完整性
- 提供完整的决策框架和思考路径
- 包含必要的背景信息和上下文
- 支持不同复杂程度的决策场景

#### 可扩展性
- 支持新游戏规则和角色扩展
- 模块化设计便于维护和更新
- 参数化设计支持个性化配置

## 状态管理

### 游戏状态结构

WerewolfAgent维护复杂的游戏状态信息，支持多轮游戏进程。

#### 核心状态字段
- **is_alive**: 智能体的存活状态
- **fake_role**: 伪装的身份角色
- **suspicion_level**: 被怀疑的程度(0.0-1.0)
- **teammates**: 已识别的狼队友列表
- **night_actions**: 夜晚行动历史记录
- **day_statements**: 白天发言历史记录
- **vote_history**: 投票历史记录

### 状态更新机制

#### 自动更新
- **行动记录**: 每次行动后自动记录到历史
- **状态计算**: 根据游戏结果更新相关状态
- **数据同步**: 与模型和其他智能体的状态同步

#### 手动更新
- **游戏事件**: 响应外部游戏事件更新状态
- **信息获取**: 根据获得的新信息更新认知
- **策略调整**: 根据策略需要主动调整状态

### 数据持久化

通过Casevo的记忆系统实现状态的持久化存储。

- **短期记忆**: 存储当前游戏会话的临时信息
- **长期记忆**: 存储跨游戏会话的经验和知识
- **搜索索引**: 支持基于语义的信息检索

## 决策算法

### 威胁评估算法

#### 评分机制
为每个潜在威胁建立量化评分系统，综合考虑多个因素：

- **角色威胁**: 不同角色的威胁权重（预言家>女巫>猎人>平民）
- **技能状态**: 技能是否已使用，剩余威胁程度
- **影响力**: 玩家在游戏中的影响力和说服力
- **位置因素**: 玩家在投票顺序、发言顺序等的位置优势
- **团队关系**: 与狼队友的关系和保护需求

#### 动态调整
根据游戏进程动态调整威胁评估：
- **早期阶段**: 重点识别神职角色
- **中期阶段**: 平衡威胁清除和身份保护
- **后期阶段**: 优先保证胜利条件达成

### 投票决策算法

#### 多目标优化
投票决策需要同时优化多个目标：
- **目标清除**: 最大化对威胁目标的清除概率
- **身份保护**: 最小化身份暴露的风险
- **团队协调**: 与狼队友的投票策略协调
- **信誉维护**: 维护"好人"形象的投票一致性

#### 概率模型
建立基于概率的投票决策模型：
- **成功概率**: 评估投票成功的可能性
- **风险概率**: 计算身份暴露的风险概率
- **收益期望**: 计算投票行为的期望收益
- **方差分析**: 考虑决策的风险和不确定性
